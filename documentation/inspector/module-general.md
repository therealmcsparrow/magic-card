# Module: General tab

The General tab of a module holds that module type's own options: its entity, text, icon, ranges, and so on. They differ per type and are listed in [Modules](../modules/README.md). Back to the [inspector overview](README.md).

## Shared keys

Every module has these keys. Only `type` is required.

| YAML key | Type | Edited in | What it does |
| --- | --- | --- | --- |
| `type` | Module type, for example `text`, `icon`, `button` | Set when you add the module | Which module this is. |
| `id` | Text | Generated by the editor | Identifies the module. Flows refer to modules by id. Optional in YAML; the card derives a stable one from the position when it is missing. |
| `entity` | Entity id, or `none` | General tab, where the type uses one | The entity the module shows or controls. Actions, conditions, animations and the ring use it as their default entity. No `entity` key follows the card entity, or the layout around the module when that layout shares its entity; `none` gives the module no entity. The Entity field is three buttons: Same as card, Pick one and No entity. See [Card entity](../card-entity/README.md). |
| `share_entity` | `true` / `false` | General tab of a layout module with an entity of its own | Share with tiles inside: the modules in the layout follow the layout's entity before the card entity. Layouts you add in the editor start with it on. |
| `actions` | Tap, hold and double tap actions | [Actions tab](actions-tab.md) | What happens when you tap the module. |
| `display` | Display conditions | [Conditions tab](conditions-tab.md) | When the module is shown. |
| `design` | Design settings | Design tab, see [Design](../design/README.md) | How the module looks. |

## Layout modules and their children

Horizontal, vertical, row, tabs and slider layout modules hold other modules. Their General tab holds only the module's own settings, such as gap and alignment, the tab style, or a row module's layout and column widths. The children are added, selected, moved and deleted in the [structure outline](../editor/structure-outline.md#layout-modules-in-the-tree):

-   Each child is an item nested under its layout module. Click it to select it. The child then gets the full inspector, with General, Actions, Conditions and Design tabs, and the header path leads back to its parent layouts.
-   The tabs of a Tabs module and the columns of a Row module are items of their own, with their own settings. See [Tabs and row-module columns](tabs-and-nested-columns.md).
-   Add module rows, and the three-dot menus, add children, tabs and columns. See [Adding rows, columns and modules](../editor/adding-structure.md#layout-modules).

Children nest to any depth, and each one supports actions, conditions and design like a top-level module.

The General tab of a Tabs module ends with the hint "Add, rename and order tabs, and add their modules, in the structure tree."

## Template-linked layout modules

On a card linked to a template, a layout module's child list is synced as one list. When a layout module or one of its children is selected, the inspector shows a note at the top:

-   "The modules inside this layout; they follow the template as one list." The list is in sync.
-   "... the layout's modules differ from the template." The list is a local override. Reset to template syncs it again.

Fields of a child have no sync indicators of their own: any change to a child makes the whole child list of its top-level layout module an override. See [the editor](../editor/README.md) for templates.
